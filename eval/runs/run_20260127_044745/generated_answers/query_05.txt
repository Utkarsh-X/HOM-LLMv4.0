## Enumerated Components

The caching system involves the following components:

1. **CacheManager**: A singleton class responsible for orchestrating the multi-layer caching strategy (cache_manager.py:1-208). It manages the interactions between different cache layers and handles cache promotion and invalidation.
2. **L1 Memory Cache (`self.memory_cache`)**: An in-memory dictionary (`Dict[str, Any]`) used for the fastest access to cached data (cache_manager.py:69). It also tracks timestamps (`self.memory_timestamps`) for TTL and LRU eviction (cache_manager.py:70, cache_manager.py:154-162).
3. **L2 Redis Cache (`self.redis`)**: An external Redis instance, managed by a `RedisClient`, providing a shared, persistent cache layer (cache_manager.py:72-80, redis_client.py:1-40). It's enabled conditionally.
4. **L3 Data Source (`fetch_func`)**: A callable function provided to the `get` method, which is responsible for retrieving the actual data from the primary data source (e.g., a database) if it's not found in L1 or L2 (cache_manager.py:92, cache_manager.py:124-125). The `CacheManager` description refers to this as the "Database cache (L3)" (cache_manager.py:5), implying the `fetch_func` retrieves from this ultimate source.
5. **Cache Key Generation (`_generate_key`)**: A utility method within `CacheManager` to create a consistent, hashed key for caching based on a namespace and identifier (cache_manager.py:82-88).

## Component Interactions

When L1 memory, L2 Redis, and L3 data source (via `fetch_func`) all miss, the `CacheManager.get` method orchestrates the following interactions and cache promotion:

1. **L1 Memory Cache Miss**:
* The `get` method first generates a cache `key` using `_generate_key` (cache_manager.py:100).
* It checks if the `key` exists in `self.memory_cache` (L1) (cache_manager.py:103).
* If the `key` is present but its timestamp indicates it has expired (i.e., `time.time() - self.memory_timestamps[key] >= ttl`), the entry is removed from L1 (cache_manager.py:106-108).
* In either case of the key not being found or being expired, a memory miss is recorded (`self.stats["memory_misses"] += 1`) (cache_manager.py:110).

2. **L2 Redis Cache Miss**:
* After an L1 miss, if Redis is enabled (`self.redis` is not `None`), the `CacheManager` attempts to retrieve the value from the L2 Redis cache using `self.redis.get(key)` (cache_manager.py:113-114).
* If `redis_value` is `None`, it signifies a miss in the L2 Redis cache. A Redis miss is recorded (`self.stats["redis_misses"] += 1`) (cache_manager.py:120).

3. **L3 Data Source Fetch (and Cache Promotion)**:
* Upon misses in both L1 and L2, the `CacheManager` checks if a `fetch_func` was provided (cache_manager.py:123).
* If `fetch_func` is available, it is executed (`value = fetch_func()`) to retrieve the data from the ultimate source (L3, e.g., a database) (cache_manager.py:125).
* **Cache Promotion**: The retrieved `value` is then promoted to both L1 and L2 caches by calling `self.set(namespace, identifier, value, ttl)` (cache_manager.py:126).
* `self.set` first calls `_set_memory(key, value, ttl)` to store the value in the L1 memory cache (cache_manager.py:147). This includes an LRU eviction policy if the memory cache limit is reached (cache_manager.py:154-162).
* Then, if Redis is enabled, `self.set` stores the value in the L2 Redis cache using `self.redis.set(key, value, ttl=ttl)` (cache_manager.py:150).
* Finally, the fetched and cached `value` is returned (cache_manager.py:127).
* If `fetch_func` was not provided and both L1 and L2 missed, `None` is returned (cache_manager.py:129).

**Cache Promotion Mechanism**:
* **L2 to L1 Promotion**: If a value is found in the L2 Redis cache (`redis_value is not None`), it is immediately promoted to the L1 memory cache by calling `self._set_memory(key, redis_value, ttl)` (cache_manager.py:117). This ensures subsequent requests for the same key will hit the faster L1 cache.
* **L3 to L1 and L2 Promotion**: When `fetch_func` successfully retrieves data from the L3 source, this data is then written to *both* the L1 memory cache and the L2 Redis cache via the `self.set` method (cache_manager.py:126, cache_manager.py:147-150). This populates the higher-level caches for future requests.

## Summary

When a request for data results in a miss across all cache layers (L1 memory, L2 Redis, and the L3 data source accessed via `fetch_func`), the `CacheManager` proceeds as follows:
1. It first checks the L1 memory cache. If the item is not found or is expired, it's an L1 miss.
2. Next, it checks the L2 Redis cache. If the item is not found there, it's an L2 miss.
3. Finally, if a `fetch_func` is provided, it is executed to retrieve the data from the ultimate L3 data source.
4. Upon successful retrieval from the L3 data source, the data is then **promoted** by being written back into both the L1 memory cache and the L2 Redis cache, making it available for faster retrieval in subsequent requests. If a value is found in L2 Redis, it is promoted to L1 memory cache. If no `fetch_func` is provided and both L1 and L2 miss, `None` is returned.
