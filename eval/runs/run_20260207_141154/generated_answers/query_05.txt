1. **CacheManager Class**: The central component responsible for orchestrating the multi-layer caching strategy. It manages the interactions between different cache levels and handles cache promotion and invalidation.
2. **L1 Memory Cache (`self.memory_cache`)**: An in-process, in-memory dictionary (`self.memory_cache`) within the `CacheManager` instance. It stores cached items along with their timestamps (`self.memory_timestamps`) for TTL and LRU eviction.
3. **L2 Redis Cache (`self.redis`)**: An external, distributed cache layer implemented using Redis. The `CacheManager` interacts with it via a `RedisClient` instance.

5. **Cache Statistics (`self.stats`)**: A dictionary within `CacheManager` that tracks hits, misses, and evictions for both memory and Redis caches.

## Component Interactions

The `CacheManager.get` method (Symbol 91) defines the interaction flow for retrieving data and handling cache misses and promotions:

1. **L1 Memory Cache Check**:
* The `get` method first generates a unique `key` for the requested `namespace` and `identifier`.
* It checks if the `key` exists in `self.memory_cache` and if its timestamp (`self.memory_timestamps[key]`) indicates it's still valid (within its `ttl`).
* **L1 Hit**: If found and valid, `self.stats["memory_hits"]` is incremented, and the value is immediately returned.
* **L1 Miss**: If the key is not found or has expired, the entry is removed (if expired), and `self.stats["memory_misses"]` is incremented. The process continues to the next cache layer.

2. **L2 Redis Cache Check**:
* After an L1 miss, if Redis is enabled (`self.redis` is not `None`), the `CacheManager` attempts to retrieve the value from Redis using `self.redis.get(key)`.
* **L2 Hit (Cache Promotion to L1)**: If `redis_value` is retrieved successfully (not `None`), `self.stats["redis_hits"]` is incremented. The value is then **promoted to the L1 memory cache** by calling `self._set_memory(key, redis_value, ttl)`. Finally, the `redis_value` is returned.
* **L2 Miss**: If `redis_value` is `None`, `self.stats["redis_misses"]` is incremented. The process continues to the ultimate data source.

3. **L3 Data Source Fetch (When L1 and L2 Miss)**:
* If both L1 memory and L2 Redis caches miss, the `get` method checks if a `fetch_func` was provided.
* **Data Fetch**: If `fetch_func` is present, it is invoked (`value = fetch_func()`). This function is assumed to retrieve the data from the primary data store (e.g., a database), which is the implied "L3 database cache" mentioned in the `CacheManager`'s docstring.
* **Cache Promotion (from Source to L1 and L2)**: Once the `value` is obtained from `fetch_func`, it is then stored in both L1 and L2 caches using the `self.set` method:
* `self.set` first calls `self._set_memory(key, value, ttl)` to store the value in the L1 memory cache. The `_set_memory` method handles **LRU eviction** if the `memory_limit` is reached, removing the least recently used item to make space.
* Then, if Redis is enabled, `self.redis.set(key, value, ttl=ttl)` is called to store the value in the L2 Redis cache.
* Finally, the fetched `value` is returned.
* **No `fetch_func`**: If no `fetch_func` is provided and all caches miss, the `get` method returns `None`.

## Summary

When L1 memory, L2 Redis, and the L3 data source (represented by `fetch_func`) all "miss" in the `CacheManager.get` operation, the following sequence of events occurs:

1. The `CacheManager` first checks its in-memory L1 cache. If the item is not found or has expired, it's an L1 miss, and the `memory_misses` statistic is incremented.
2. Next, it checks the L2 Redis cache. If Redis is enabled and the item is not found there, it's an L2 miss, and the `redis_misses` statistic is incremented.
3. Finally, with both L1 and L2 caches having missed, the `CacheManager` invokes the provided `fetch_func`. This function is responsible for retrieving the actual data from the ultimate source, which is implicitly the "L3 database" or primary data store.
4. Upon successful retrieval of the `value` from the `fetch_func`, **cache promotion** immediately takes place. The `value` is first stored in the L1 memory cache (handling LRU eviction if the memory limit is reached) and then, if Redis is enabled, it is also stored in the L2 Redis cache. This ensures that subsequent requests for the same data will hit the faster L1 or L2 caches.

Cache promotion also occurs if there's an L1 miss but an L2 Redis hit. In this scenario, the value retrieved from Redis is promoted to the L1 memory cache to make it available faster for future requests.
