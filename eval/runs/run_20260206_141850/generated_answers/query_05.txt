## Enumerated Components
* **CacheManager (Symbol: 21):** The primary class responsible for orchestrating the multi-layer caching strategy.
* **Memory Cache (L1):** An in-process cache managed by `CacheManager` using `self.memory_cache` (a dictionary for values) and `self.memory_timestamps` (a dictionary for tracking access times).
* **Redis Cache (L2):** An external, distributed cache managed by an instance of `RedisClient` (Symbol: 42), accessible via `self.redis` within `CacheManager`.
* **Database/Original Data Source (L3):** Represented by a `fetch_func` callable argument passed to the `CacheManager.get` method, which is responsible for retrieving data when it's not found in L1 or L2.
* **`CacheManager.get` method (Symbol: 91):** The core method that implements the cache lookup logic, including checking each layer and handling cache promotion.
* **`CacheManager._set_memory` method (Symbol: 160):** An internal helper method used to add or update entries in the L1 memory cache, incorporating an LRU eviction policy.
* **`CacheManager.set` method (Symbol: 139):** A method used to explicitly set a value across multiple cache layers (L1 and L2).

## Component Interactions
When a request is made to `CacheManager.get(namespace, identifier, fetch_func, ttl)`:

1. **L1 Memory Cache Lookup:**
* The `CacheManager` first generates a `key` from the `namespace` and `identifier`.
* It checks if this `key` exists in `self.memory_cache`.
* If the `key` is found and the entry has not expired (checked against `self.memory_timestamps` and the provided `ttl`), it's considered a memory hit. The `memory_hits` statistic is incremented, and the value is returned immediately.
* If the `key` is found but expired, the entry is removed from `self.memory_cache` and `self.memory_timestamps`.
* If the `key` is not found or was expired, it's a memory miss, and the `memory_misses` statistic is incremented.

2. **L2 Redis Cache Lookup (if L1 misses):**
* If the L1 memory cache misses, and if Redis is enabled (`self.redis` is not `None`), the `CacheManager` attempts to retrieve the value from the Redis cache using `self.redis.get(key)`.
* If a `redis_value` is successfully retrieved from Redis, it's a Redis hit. The `redis_hits` statistic is incremented.
* **Cache Promotion (L2 to L1):** The `redis_value` is then promoted to the L1 memory cache by calling `self._set_memory(key, redis_value, ttl)`. This ensures that subsequent requests for the same key will hit the faster L1 cache. The `redis_value` is then returned.
* If the value is not found in Redis (`redis_value` is `None`), it's a Redis miss, and the `redis_misses` statistic is incremented.

3. **L3 Database/Source Fetch (if L1 and L2 miss):**
* If both the L1 memory cache and the L2 Redis cache miss, the `CacheManager` checks if a `fetch_func` (a callable function) was provided as an argument to `get`.
* If `fetch_func` is provided, it is executed (`value = fetch_func()`) to retrieve the data from the original source (conceptually the L3 database or backend service).
* **Cache Promotion (L3 to L1 and L2):** The newly fetched `value` is then stored in both the L1 memory cache and the L2 Redis cache by calling `self.set(namespace, identifier, value, ttl)`. The `set` method internally calls `self._set_memory` for L1 and `self.redis.set` for L2. The fetched `value` is then returned.
* If `fetch_func` is *not* provided and all caches miss, the `get` method returns `None`.

**Cache Promotion Mechanism (`_set_memory`):**
* The `_set_memory` method, used for promoting values to the L1 memory cache, first checks if the memory cache has reached its `memory_limit`.
* If the limit is reached, it performs an LRU (Least Recently Used) eviction: it identifies the `oldest_key` by finding the minimum timestamp in `self.memory_timestamps`, removes that key from both `self.memory_cache` and `self.memory_timestamps`, and increments the `evictions` statistic.
* Finally, the new `key` and `value` are added to `self.memory_cache`, and their access timestamp is recorded in `self.memory_timestamps`.

## Summary
When a cache request results in a miss across all layers (L1 memory, L2 Redis, and L3 database/original source), the `CacheManager`'s `get` method systematically attempts to retrieve the data. It first checks L1 (memory), then L2 (Redis). If both miss, it executes a provided `fetch_func` to retrieve the data from the ultimate source (L3). Upon successful retrieval from a lower layer, the data is automatically promoted to the higher, faster cache layers. Specifically, data found in Redis (L2) is promoted to the memory cache (L1), and data fetched from the original source (L3) is promoted to both the memory cache (L1) and the Redis cache (L2). The L1 memory cache manages its size using an LRU eviction policy during promotion. If no `fetch_func` is provided and all caches miss, the operation concludes by returning `None`.
