The `BatchProcessor` handles partial failures by processing items in batches and continuing execution even if individual batches fail. However, it does not intrinsically implement at-least-once semantics; it provides the necessary information for a higher-level system to do so.

Here's how it works:

1. **Batch Processing and Error Isolation**:
* The `BatchProcessor` splits the input `items` into smaller `batches` based on the configured `batch_size` (batch_processor.py:44-47).
* It iterates through these batches, calling a `processor_func` for each one (batch_processor.py:52-54).
* Each batch's processing is wrapped in a `try...except` block (batch_processor.py:53). If the `processor_func` fails for a particular batch, the exception is caught.
* This allows the processing of subsequent batches to continue, preventing a single batch failure from halting the entire operation (batch_processor.py:52-64).

2. **Reporting Partial Failures**:
* When a batch fails, an error message is appended to an `errors` list within the `BatchProcessor` (batch_processor.py:58).
* The `failed_count` is incremented by the number of items in the failed batch (batch_processor.py:59).
* An optional `error_handler` can be provided to execute custom logic upon a batch failure (batch_processor.py:61-62).
* The `process` method returns a `BatchResult` object which includes `total_items`, `processed_items`, `failed_items`, and a list of `errors` (batch_processor.py:74-82). This result clearly indicates which batches (and thus which items) failed.

3. **At-Least-Once Semantics**:
* Based on the provided code, the `BatchProcessor` itself **does not implement at-least-once semantics** intrinsically.
* If a batch fails, the items within that batch are marked as `failed_items` and their errors are recorded (batch_processor.py:58-59). There is no built-in retry mechanism within the `BatchProcessor` to re-process these failed items or batches automatically.
* To achieve at-least-once semantics, the *caller* of the `BatchProcessor.process` method would need to inspect the `BatchResult` (specifically the `failed_items` and `errors` lists) and then re-submit the failed items for processing. Alternatively, the `processor_func` itself would need to be designed to be idempotent and handle retries internally.
