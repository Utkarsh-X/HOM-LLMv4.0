## Enumerated Components

The system involves the following key components and optimization rules:

**Optimizer Rules (as applied by `Optimizer.optimize`):**
1. **Predicate Pushdown:** (`_apply_predicate_pushdown`) Filters data as early as possible in the query plan to reduce the amount of data processed by subsequent operations.
2. **Projection Pushdown:** (`_apply_projection_pushdown`) Selects only the necessary columns at the earliest possible stage, minimizing data transfer and processing.
3. **Constant Folding:** (`_apply_constant_folding`) Evaluates constant expressions at query planning time, simplifying filters or computations.
4. **Index Selection:** (`_apply_index_selection`) Chooses the most efficient index (if available) for data retrieval, improving scan performance.
5. **Join Reordering:** (`_apply_join_reordering`) Rearranges the order of join operations to minimize intermediate result set sizes and overall join cost.

**Other Key Components:**
* **QueryPlanner:** Manages the generation and caching of query execution plans.
* **QueryPlan:** Represents an ordered sequence of execution steps (`PlanStep`) for a query, including estimated costs and output rows.
* **Optimizer:** Applies a series of rules to transform an initial query representation (`QueryOperations`) into a more efficient `OptimizedQuery`.
* **OptimizedQuery:** The result of the optimization process, containing the original and optimized query operations, estimated cost, and optimization time.
* **ExecutionContext:** Tracks the timing and state of a single query's execution, including start/end times, duration, and processed rows.
* **ExecutionEngine:** Manages multiple `ExecutionContext` instances and aggregates overall execution statistics.

This integrated approach ensures that queries benefit from performance improvements through optimization and reduced planning overhead via caching, all while providing detailed timing metrics.
