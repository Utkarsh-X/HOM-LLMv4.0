## Summary
When a request for data results in a miss across all three cache layers (L1 memory, L2 Redis, and L3 database/source), the `CacheManager` orchestrates a sequential lookup. It first checks the L1 memory cache. If that misses, it checks the L2 Redis cache. If both L1 and L2 miss, it invokes a provided `fetch_func` to retrieve the data from the ultimate source (L3).

Cache promotion is an integral part of this process:
* **L2 to L1 Promotion:** If data is found in the L2 Redis cache after an L1 memory cache miss, it is immediately copied and stored in the L1 memory cache. This ensures that subsequent requests for the same data benefit from the fastest available cache layer.
* **L3 to L1 and L2 Promotion:** If data must be fetched from the L3 source (via `fetch_func`) due to misses in both L1 and L2, the retrieved data is then written back to *both* the L1 memory cache and the L2 Redis cache. This populates the higher cache tiers, making the data readily available for future requests without needing to hit the slower L3 source again. The L1 memory cache also handles LRU eviction if its capacity limit is reached during this promotion.
