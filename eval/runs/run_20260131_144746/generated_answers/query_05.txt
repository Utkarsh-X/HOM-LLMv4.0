## Summary
When a request for data results in a miss across all cache layers (L1 memory, L2 Redis, and L3 database/source), the `CacheManager`'s `get` method sequentially checks each layer. It first attempts to retrieve the data from the L1 memory cache. If not found or expired, it proceeds to the L2 Redis cache. If the data is still not found, it then invokes a provided `fetch_func` (representing the L3 database or original data source) to retrieve the actual value.

Cache promotion is an automatic process that moves data from slower, deeper cache layers to faster, shallower ones upon a successful retrieval. If data is found in L2 Redis, it is promoted and stored in L1 memory. If data is retrieved from the L3 source via `fetch_func`, it is then promoted and stored in both L1 memory and L2 Redis, ensuring that subsequent requests for the same data can be served more quickly from the higher-tier caches. The L1 memory cache also implements an LRU eviction policy to manage its size.
