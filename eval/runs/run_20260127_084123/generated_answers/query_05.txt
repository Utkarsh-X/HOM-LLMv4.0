## Summary
When a request for data results in a miss across all cache layers (L1 memory, L2 Redis, and the underlying L3 data source, typically a database), the `CacheManager`'s `get` method follows a specific sequence. It first checks L1 memory, then L2 Redis. If both miss, it invokes a provided `fetch_func` to retrieve the data from its original source. Upon successful retrieval from the source, the data is then promoted upwards through the cache hierarchy: it is first stored in the L1 memory cache (potentially triggering an LRU eviction if the memory limit is reached) and then also stored in the L2 Redis cache. This ensures that subsequent requests for the same data can be served more quickly from the higher, faster cache layers. Cache promotion also occurs when data is found in L2 Redis after an L1 miss, where it is then copied to L1 memory.
