## Component Interactions
The `BatchProcessor` orchestrates the processing of a collection of items by interacting with several key components:

1. **`processor_func` (Callable[[List[T]], List[U]]):** The `BatchProcessor` invokes this function for each batch of items. It passes a `List[T]` (a batch of input items) to `processor_func`, expecting a `List[U]` (a list of processed results) in return if successful. This is the core logic that performs the actual work on the items.
2. **`error_handler` (Optional[Callable[[Exception], None]]):** If the `processor_func` raises an `Exception` while processing a batch, the `BatchProcessor` catches this exception and, if an `error_handler` is provided, calls it with the caught `Exception`. This allows for custom, external handling of batch-level failures.
3. **`logger`:** The `BatchProcessor` interacts with a `logger` (implicitly available in the context) to record informational messages (e.g., start of processing, batch completion) and error messages when a batch fails.
4. **`BatchResult`:** Upon completion of all batches, the `BatchProcessor` aggregates all collected results, error messages, and statistics (total items, processed items, failed items, duration) into a `BatchResult` object, which is then returned to the caller.
5. **Internal State (`batch_stats`):** The `BatchProcessor` updates its internal `batch_stats` dictionary with cumulative metrics such as `batches_processed`, `total_items`, `failed_items`, and `total_duration_ms` after each `process` call.
