## Enumerated Components
* **CacheManager:** The primary class responsible for orchestrating the multi-layer caching system. It manages the flow of cache lookups, misses, and promotions across different layers.
* **Memory Cache (L1):** An in-process cache implemented as a Python dictionary (`self.memory_cache`) within the `CacheManager` instance. It stores cached values and their timestamps (`self.memory_timestamps`) for time-to-live (TTL) management and Least Recently Used (LRU) eviction.
* **Redis Cache (L2):** An external, persistent cache layer accessed via a `RedisClient` instance (`self.redis`) within the `CacheManager`. It provides a shared caching mechanism across processes.
* **Database/Primary Data Source (L3):** The ultimate source of truth for the data. While the `CacheManager` description explicitly mentions "Database cache (L3)", the direct interaction with this layer in the `get` method is abstracted through a `fetch_func` callable.
* **`fetch_func`:** A callable function provided to the `CacheManager.get` method. This function is responsible for retrieving the actual data from the L3 database or primary data source when both L1 and L2 caches miss.

## Component Interactions
The `CacheManager.get` method defines the interaction flow when a value is requested, including how cache misses are handled and how cache promotion occurs:

1. **L1 Memory Cache Check:**
* The `CacheManager` first attempts to retrieve the value from its `self.memory_cache` (L1) using a generated key.
* If the key exists and the entry has not expired (checked against `self.memory_timestamps` and the `ttl`), a `memory_hits` statistic is incremented, and the value is returned.
* If the key exists but is expired, the entry is removed from L1.
* If the key is not found or was expired, a `memory_misses` statistic is incremented, and the process moves to L2.

2. **L2 Redis Cache Check:**
* If L1 misses and Redis is enabled (`self.redis` is not `None`), the `CacheManager` attempts to fetch the value from the Redis instance using `self.redis.get(key)`.
* If the value is found in Redis, a `redis_hits` statistic is incremented.
* **Cache Promotion (L2 to L1):** The retrieved `redis_value` is then immediately promoted to the L1 memory cache by calling `self._set_memory(key, redis_value, ttl)`. This ensures that subsequent requests for the same data will hit the faster L1 cache. The `redis_value` is then returned.
* If the value is not found in Redis, a `redis_misses` statistic is incremented, and the process moves to the L3 source.

3. **L3 Database/Primary Data Source Fetch (All Caches Miss):**
* If both L1 and L2 caches miss, the `CacheManager` checks if a `fetch_func` was provided.
* **Data Retrieval:** If `fetch_func` is provided, it is executed (`value = fetch_func()`) to retrieve the data from the ultimate source (the L3 database/primary data source).
* **Cache Promotion (L3 to L1 and L2):** The newly fetched `value` is then written back to *both* the L1 memory cache and the L2 Redis cache using the `self.set(namespace, identifier, value, ttl)` method.
* The `set` method first calls `self._set_memory(key, value, ttl)` to store the value in L1. This method includes an LRU eviction policy, removing the oldest entry if the `memory_limit` is reached.
* Then, if Redis is enabled, `self.redis.set(key, value, ttl=ttl)` stores the value in L2.
* The fetched `value` is then returned.

4. **No Value Found:**
* If L1 and L2 miss, and no `fetch_func` is provided, or if the `fetch_func` returns `None`, the `CacheManager.get` method ultimately returns `None`.

## Summary
When a request for data results in a miss across all three cache layers (L1 memory, L2 Redis, and L3 database/primary data source), the `CacheManager` performs the following actions:
1. It first checks the L1 memory cache. If the item is not found or is expired, it's a memory miss.
2. It then checks the L2 Redis cache. If the item is not found, it's a Redis miss.
3. Upon a miss in both L1 and L2, the `CacheManager` invokes a `fetch_func` (if provided). This function is responsible for retrieving the data from the ultimate source, which is designated as the L3 database/primary data source.
4. Once the data is successfully retrieved by the `fetch_func`, it is then promoted back up the cache hierarchy. This promotion involves writing the fetched value to both the L1 memory cache (using `_set_memory`, which handles LRU eviction) and the L2 Redis cache (using `self.redis.set`). This ensures that subsequent requests for the same data will be served from the faster, higher-tier caches, improving performance. If no `fetch_func` is provided or it fails to retrieve data, `None` is returned.
