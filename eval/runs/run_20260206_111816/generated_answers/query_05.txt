## Summary
When a request for data results in a miss across all cache layers (L1 memory, L2 Redis, and the conceptual L3 database/source), the `CacheManager` follows a specific retrieval and promotion process:

1. **L1 Memory Miss**: The initial check in the fast in-memory cache fails, and the system proceeds to the next layer.
2. **L2 Redis Miss**: The request then checks the Redis cache. If the data is not found there either, it's considered an L2 miss.
3. **L3 Source Fetch**: With both L1 and L2 caches missing, the `CacheManager` executes a provided `fetch_func`. This function is responsible for retrieving the data from its original, authoritative source (e.g., a database or a backend service), which is the slowest but most reliable layer.
4. **Cache Promotion**: Once the data is successfully fetched from the source, it is immediately promoted and written back into both the L1 memory cache and the L2 Redis cache. This ensures that the newly retrieved data is available in the faster cache layers for subsequent requests, improving performance.

Cache promotion also occurs when data is found in the L2 Redis cache after an L1 miss. In this case, the data from Redis is promoted to the L1 memory cache, making it readily available for future access without needing to query Redis again.
