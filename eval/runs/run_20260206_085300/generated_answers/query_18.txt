## Enumerated Components

The following components are involved in query optimization, plan caching, and execution timing:

**Optimizer Rules (5 rules applied by `QueryOptimizer`):**
1. **Predicate Pushdown (`_apply_predicate_pushdown`):** Reorders filters by selectivity to apply the most restrictive ones first.
2. **Projection Pushdown (`_apply_projection_pushdown`):** Removes unnecessary columns from the projection list, keeping only those required for output, filters, or joins.
3. **Constant Folding (`_apply_constant_folding`):** Evaluates constant expressions within filters to simplify them or remove conditions that are always true/false.
4. **Index Selection (`_apply_index_selection`):** Chooses the most beneficial index from `available_indices` based on filter conditions.
5. **Join Reordering (`_apply_join_reordering`):** Reorders joins based on their estimated cost to find a more efficient join order.

**Plan Caching Components:**
* **`plan_query` method:** The entry point for generating and retrieving query plans.
* **`plan_cache` (dictionary):** Stores `QueryPlan` objects, keyed by `cache_key`.
* **`_make_cache_key` method:** Generates a unique key for caching a query plan.
* **`enable_caching` (boolean):** Controls whether plan caching is active.
* **`plan_stats` (dictionary):** Tracks cache hits, misses, and plans generated.
* **`QueryPlan` class:** Represents the execution plan, containing a `plan_id` (cache key) and a list of `PlanStep`s.

**Execution Timing Components:**
* **`QueryOptimizer.optimize` method:** Records `optimization_time_ms` for the entire optimization process.
* **`OptimizedQuery` class:** Stores `optimization_time_ms` as part of the optimization result.
* **`QueryOptimizer.optimization_stats` (dictionary):** Aggregates `optimization_time_ms` across all optimized queries.
* **`ExecutionEngine.execute` method:** Initiates query execution and creates an `ExecutionContext`.
* **`ExecutionContext` class:** Tracks the `start_time`, `end_time`, and `duration_ms` for the overall query execution. It also records `execution_stages` with `duration_ms` for each individual `PlanStep`.
* **`ExecutionEngine.execution_stats` (dictionary):** Aggregates `total_duration_ms` for all executed queries.
