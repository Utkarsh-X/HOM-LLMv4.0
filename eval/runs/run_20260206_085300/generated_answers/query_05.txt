## Component Interactions

When a request is made to retrieve a value using `CacheManager.get(namespace, identifier, fetch_func, ttl)`:

1. **L1 Memory Cache Lookup:**
* The `CacheManager` first generates a unique `key` for the requested item (using `_generate_key`, Symbol: 83).
* It then checks if this `key` exists in `self.memory_cache` (L1).
* If the item is found and is not expired (checked against `self.memory_timestamps` and the `ttl`), a "memory hit" is recorded, and the value is returned immediately (Symbol: 91, lines 19-21).
* If the item is found but has expired, it is removed from the memory cache.
* If the item is not found or was expired, a "memory miss" is recorded (Symbol: 91, line 25).

2. **L2 Redis Cache Lookup (if L1 misses):**
* If the L1 memory cache misses, and if Redis is enabled (`self.redis` is not None), the `CacheManager` attempts to retrieve the value from the Redis cache using `self.redis.get(key)` (Symbol: 91, line 29).
* **Cache Promotion (L2 to L1):** If the value is successfully retrieved from Redis, a "Redis hit" is recorded. The value is then *promoted* to the L1 memory cache by calling `self._set_memory(key, redis_value, ttl)` (Symbol: 91, line 32). This ensures that the value is available in the faster L1 cache for subsequent requests. The value is then returned.
* If the value is not found in Redis, a "Redis miss" is recorded (Symbol: 91, line 35).

3. **L3 Database/Source Fetch (if L1 and L2 both miss):**
* If both the L1 memory cache and the L2 Redis cache miss, and a `fetch_func` was provided to the `get` method, this function is executed: `value = fetch_func()` (Symbol: 91, line 38). This `fetch_func` is responsible for fetching the data from the ultimate source of truth, which the `CacheManager`'s documentation refers to as the "Database cache (L3)".
* **Cache Promotion (Source to L1 and L2):** Once the `value` is successfully retrieved from the source by `fetch_func`, it is then stored in *both* the L1 memory cache and the L2 Redis cache by calling `self.set(namespace, identifier, value, ttl)` (Symbol: 91, line 39).
* The `set` method (Symbol: 21, lines 150-160) first calls `self._set_memory(key, value, ttl)` to store it in L1, handling LRU eviction if the memory limit is reached.
* Then, if Redis is enabled, it calls `self.redis.set(key, value, ttl=ttl)` to store it in L2.

## Summary

When a request for data results in a miss across all cache layers (L1 memory, L2 Redis, and the L3 source represented by `fetch_func`), the `CacheManager` proceeds as follows:

1. **L1 Memory Miss:** The initial check of the in-memory cache (`self.memory_cache`) fails to find the item or finds an expired item.
2. **L2 Redis Miss:** Subsequently, the `CacheManager` queries the Redis cache. If the item is not found there, it's considered a Redis miss.
3. **L3 Source Fetch:** With both L1 and L2 caches having missed, the `CacheManager` executes the provided `fetch_func`. This function is responsible for retrieving the data from its primary source (e.g., a database).

**Cache Promotion Mechanism:**
* **L2 to L1 Promotion:** If a value is successfully retrieved from the L2 Redis cache, it is immediately promoted and stored in the L1 memory cache. This ensures that subsequent requests for the same data benefit from the faster in-memory access.
* **Source (L3) to L1 and L2 Promotion:** When the `fetch_func` successfully retrieves data from the ultimate source, this data is then promoted and stored in *both* the L1 memory cache and the L2 Redis cache. This populates the higher-level caches, making the data available for faster retrieval in future requests.

If no `fetch_func` is supplied and all cache layers miss, the `CacheManager` indicates that the value could not be found by returning `None`.
