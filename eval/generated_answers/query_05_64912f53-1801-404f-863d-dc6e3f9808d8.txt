When L1 memory, L2 Redis, and the L3 data source (represented by a `fetch_func`) all miss, the following sequence of events occurs within the `CacheManager`'s `get` method:

1. **L1 Memory Cache Miss:**
* The `CacheManager` first attempts to retrieve the value from its in-memory cache (`self.memory_cache`) using a generated key (:117-118).
* If the key is not found in `self.memory_cache` or if the entry has expired based on its timestamp and TTL, it's considered a memory miss (:120-126).
* The `memory_misses` statistic is incremented (:128).

2. **L2 Redis Cache Miss:**
* After an L1 miss, if Redis is enabled (`self.redis` is not None), the `CacheManager` attempts to retrieve the value from the Redis cache (:130-131).
* If `self.redis.get(key)` returns `None`, it signifies a Redis cache miss (:132).
* The `redis_misses` statistic is incremented (:136).

3. **L3 Data Source Fetch (Database Miss):**
* Since both L1 and L2 caches missed, the `CacheManager` checks if a `fetch_func` was provided (:138).
* If `fetch_func` is present, it is executed to retrieve the value from the ultimate data source (e.g., a database) (:139). The `CacheManager` itself does not directly interact with a "database cache" layer; instead, it relies on this `fetch_func` to get the data from its origin.

**Cache Promotion:**

Cache promotion occurs when data is successfully retrieved from a lower-level cache or the original data source, and then stored in higher-level caches to make future access faster.

* **Promotion from L2 Redis to L1 Memory:** If the value is found in the L2 Redis cache (`redis_value is not None`), it is immediately promoted and stored in the L1 memory cache using the `_set_memory` method (:133-134). This ensures that subsequent requests for the same data will hit the faster L1 cache.

* **Promotion from L3 Data Source to L1 Memory and L2 Redis:** If the `fetch_func` successfully retrieves the value (meaning both L1 and L2 missed), this newly fetched value is then set in *both* the L1 memory cache and the L2 Redis cache using the `set` method (:139-140).
* The `set` method calls `_set_memory` to store the value in the L1 memory cache (:160).
* It also calls `self.redis.set` to store the value in the L2 Redis cache, if Redis is enabled (:163-164).

The `_set_memory` method also handles an LRU (Least Recently Used) eviction policy for the memory cache. If the memory cache reaches its `memory_limit`, the oldest entry (based on timestamp) is removed to make space for the new entry, and the `evictions` statistic is incremented (:168-173).
